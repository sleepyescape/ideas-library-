# ideas-library

Библиотека референсов для генераций + плагины Claude Code, которые работают без установки.
Владелец пишет по-русски, часто с телефона — отвечай по-русски, коротко и с готовыми шагами.
Владелец работает в облачных сессиях (приложение Claude, claude.ai/code).

## Главное ограничение облака

Облачные сессии **НЕ устанавливают** плагины из `enabledPlugins` / `extraKnownMarketplaces`
в `.claude/settings.json` (ни свои, ни чужие). В облаке работают только:
- `.claude/skills/`, `.claude/commands/`, `.claude/agents/` из репозитория;
- хуки и permissions из `.claude/settings.json`, MCP из `.mcp.json`;
- плагины и навыки, включённые в аккаунте claude.ai.

Поэтому плагин «работает» для владельца, только если его навыки/команды попали в `.claude/`.

## Плагины: как добавлять по просьбе владельца

Владелец присылает ссылку, название или ролик (TikTok и т. п.) и просит «установи плагины».

1. **Найди плагин.** Если прислан ролик — вытащи кадры ffmpeg-ом (`fps=1/3`, склейка `tile=4x2`)
   и прочитай названия. Найди репозиторий на GitHub, склонируй в scratchpad и проверь:
   лицензию, что внутри (skills / commands / agents / hooks / MCP), какие внешние программы нужны.
2. **Подключи правильным способом:**
   - **Навыки, команды, агенты** (в т. ч. чужие, если лицензия позволяет: MIT, Apache, CC BY…) —
     положи в `plugins/<имя>/` (`skills/`, `commands/`, `agents/`), чужое — без изменений,
     с LICENSE и `README.md` (автор, ссылка, коммит). Затем `python3 tools/plugins.py sync`
     скопирует их в `.claude/`. Так работает и в облаке, и на ПК.
   - **Плагин держится на хуках, прокси или локальной программе** (как claude-mem, headroom) —
     в облаке он бесполезен. Подключи для ПК через `.claude/settings.json`
     (`extraKnownMarketplaces` + `enabledPlugins`) и честно скажи владельцу, что в облаке
     он работать не будет. Вариант для облака — включить плагин в аккаунте claude.ai.
   - **Это не плагин** (сервер, шлюз, как OmniRoute) — не ставь, опиши в `plugins/README.md`.
   - **Это инструкция без плагина** (например, гайд за Telegram-ботом) — можно написать
     свой навык в `plugins/<имя>/skills/`, не копируя чужой платный контент.
3. После правок: `python3 tools/plugins.py sync`, обнови таблицы в `plugins/README.md`.
4. Перед подключением стороннего кода коротко скажи владельцу, что это за код, и получи «да».
   Если авто-фильтр блокирует коммит/пуш, не обходи его: попроси переключить режим на
   **Accept edits** и написать «пушь».
5. Коммит в отдельную ветку → pull request в `main` → владелец сам жмёт
   **Merge pull request → Confirm merge**. Сам не сливай.
6. Не говори «работает», пока не проверено: навыки и команды появляются только в **новой**
   сессии после слияния в `main`. Попроси владельца открыть новую сессию и проверить.

## Устройство

- `plugins/` — исходники; `plugins/README.md` — инструкция и список всего подключённого.
- `.claude/skills|commands|agents/` и `.claude/plugins-mirror.json` — генерирует
  `tools/plugins.py sync`, руками не править (правь в `plugins/` и запускай `sync`).
- `.claude-plugin/marketplace.json` — генерируется `sync`, для ручной установки на ПК.
- `.claude/settings.json` — чужие плагины для ПК. `sync` их не трогает.
- `.github/workflows/sync-plugins.yml` — запускает `sync` после загрузки в `plugins/` через
  сайт GitHub (разрешение Read and write у Actions владелец уже включил).
